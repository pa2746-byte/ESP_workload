Rodinia: captured execution versus Clang dependencies

Tesla T4 · capture 20261027T033003Z · 513 NN records; HotSpot3D 64×64×3, two iterations · deterministic synthetic inputs.

Result: operation structure matches; dependency semantics differ

Both traces match source-predicted kernel names, counts, launch dimensions, and explicit copy directions and sizes. All modeled dependencies are consistent with the observed order. This does not independently verify every kernel read/write footprint.

Nearest Neighbor: the four Clang access nodes collapse to three operations: upload → euclid → download. This matches the three-event execution DAG.

HotSpot3D: nine Clang access nodes collapse to five operations. The observed chain is upload temperature → upload power → iteration 1 → iteration 2 → download. Stream order adds constraints beyond the buffer DAG.

The important difference: the source-derived download depends on iteration 1's output, even though it executes after iteration 2. The source swaps pointers and downloads the previous buffer. The trace lacks buffer addresses here, so it cannot independently confirm the downloaded buffer's identity. Do not replace the source dependency with an iteration-2 producer edge merely because of timing.

Clang read/write volumes are unique logical footprints. Trace copy bytes describe explicit copies. Kernel nodes deliberately have no physical-traffic volume; zero would be misleading. Stream-order edges do not carry buffer sizes.

Limits and simulator use

  • One profiled execution per workload; microsecond durations include profiling effects. These are observations, not stable performance estimates.
  • GPU event sums exclude host setup and gaps; event spans include gaps but still exclude application startup and CPU processing.
  • No cache, DRAM-traffic, internal synchronization, or numerical correctness validation. HotSpot's printed Accuracy alone is not proof of correctness.
  • Source/config hashes match the bundle. NN uses the recorded legacy API compatibility macro. Clang device configuration is synthetic, but actual launch dimensions match.
  • Use Clang for buffer relationships and the trace for operation timing and stream order. Preserve both edge types in a combined simulator model.
  • This extractor intentionally rejects multiple streams, contexts, processes or submitting threads; arbitrary traces require explicit event/synchronization analysis.
